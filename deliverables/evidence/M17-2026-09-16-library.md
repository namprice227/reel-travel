## Browser reproduction

The browser runner uses real page rendering with intercepted synthetic trip/save/place responses. Save, screenshot upload, recovery, retry and skip calls in that runner are intercepted. The separate API smoke above exercises real services. Only the runner's dev sign-in creates a new example.test account. No private user data is captured.

```powershell
# Keep the application running with npm run dev.
npm install --prefix .local/browser-tools --no-package-lock --no-save playwright
# Point to an existing Chromium executable if the default Playwright browser is unavailable.
$env:PLAYWRIGHT_EXECUTABLE_PATH = 'C:/path/to/chrome.exe'
node --import tsx tests/e2e/library.mjs
```

The runner defaults to the ignored `.local/browser-tools` package, accepts `PLAYWRIGHT_MODULE_PATH` for a different package entry, and uses `SMOKE_BASE_URL` when set. It writes screenshots under `.local/library-browser`. Those local screenshots are synthetic UI evidence, not real travel-place evidence.

## Limits

No participant usability study, human visual acceptance, real AI/provider measurement or production deployment was performed. Only Chromium is covered by the automated browser pass. Country lookup is a temporary deterministic fallback, not global geocoding. Browser-intercepted source uploads do not prove private asset authorization; service isolation is covered separately by the existing tests.
